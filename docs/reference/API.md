# The local API

> What the page, and later the browser extension, call. The code is `board/server.py` (routes, checks) and `board/items.py` (what each route does); this page is for a client's author. Errors are always `{"error": "<plain text>"}`, with no path in them.

The server listens on `127.0.0.1` only. Everything outside `/api` that is read (GET, HEAD) is the built page from `web/dist/`: `/` is its `index.html`, and other addresses are its `.html`, `.js`, `.css`, `.woff` and `.woff2` files, never a hidden name, a link out of the folder or a query; any other address there is a 404. The same `Host` and `Origin` checks apply to it. A request's `Host` must be `127.0.0.1:<port>` or `localhost:<port>`; a request that changes anything (POST, DELETE) must carry an `Origin` of the same address, and a request with any other `Origin` is refused with 403. No CORS header is ever sent. A body is JSON with `Content-Type: application/json` and a `Content-Length`; the limit is about 34 MB (a 25 MB image in base64).

| Request | Answer |
|---|---|
| `GET /api/brands` | `{"brands": ["slug", ...]}`, alphabetical |
| `GET /api/brands/<slug>` | `{slug, status, client, summary, hub_problem, panels: [{title, text, problem, date}], moodboard: {exists, problem, items: [...]}}`; items newest first; text is plain, never escaped |
| `GET /api/brands/<slug>/images/<id>.<ext>` and `.../thumbs/<id>.<ext>` | the image bytes, with their own `Content-Type`; cacheable for a year (an id never changes), every other answer is `no-store` |
| `GET /api/brands/<slug>/links/<hash>.<ext>` | the thumbnail of an address's preview picture, the address being an item's `preview.url`; same headers as an image; 404 when none is kept |
| `POST /api/brands/<slug>/items` with `{description, source, image, lookup}` | 201 and the new item; the first three fields are optional but at least one must be there; `image` is base64 or null; `lookup` is optional, true or false (true if left out), anything else is 400 |
| `DELETE /api/brands/<slug>/items/<key>` | `{"deleted": "<key>"}`; the key is the item's `key` from the brand view. If the block went but its image files could not be removed, still 200, with `"warning": "<plain text>"` added (never a path) |

An item is `{key, text, description, source, image, thumb, width, height, date, title, preview}`: `image` and `thumb` are addresses, or null for an item with no image (or whose embed was written by hand, which the app never serves); `width` and `height` are the thumbnail's size in pixels, or null when there is none or it cannot be read. `title` and `preview` come from the address lookup of ADR 008 and are null for an item with no address, an item with an image of its own, an address that was not looked up or whose lookup got nothing; `title` is the page's title as plain text, and `preview` is `{url, width, height}` of a thumbnail the app serves (so the page still loads nothing from another site). When an item is added with an address, no image and `lookup` not false, the server fetches that page once before answering (up to eight seconds); an address already looked up in that brand is not fetched again, and a failure is silent: the answer is still 201 with `title` and `preview` null. The title is never written into the note. Deleting an item also removes the kept lookup unless another block in the Moodboard has the same address. A panel's `date` is its note's frontmatter `created` (`YYYY-MM-DD`, or `YYYY-MM-DDTHH:MM` when it has a time; seconds and a zone are dropped), or null. An item's `date` is the one in its image id, as `YYYY-MM-DDTHH:MM`; in a brand's list an item with no image of the app's own takes the date of the item before it, in the order they were added, and one before any dated item has none. The page uses both to order its cards. `<slug>` is the folder name under `Brands/`, quoted in the address.

Statuses: 400 a body that cannot be read; 403 a refused origin or host, or a folder the app will not write in; 404 no such brand, image or route; 409 the brand has no Moodboard note (the app creates none), the item changed or is duplicated since it was shown, or the note changed while it was being written (nothing was written; try again); 408 the client stopped sending (30 seconds); 411 no length; 413 too big; 415 not JSON; 422 an image, address or description that cannot be taken; 500 something went wrong.
