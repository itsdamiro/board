# The local API

> What the page, and later the browser extension, call. The code is `board/server.py` (routes, checks) and `board/items.py` (what each route does); this page is for a client's author. Errors are always `{"error": "<plain text>"}`, with no path in them.

The server listens on `127.0.0.1` only. Everything outside `/api` that is read (GET, HEAD) is the built page from `web/dist/`: `/` is its `index.html`, and other addresses are its `.html`, `.js`, `.css`, `.svg` (the favicon, sent with the SVG policy of ADR 008), `.woff` and `.woff2` files, never a hidden name, a link out of the folder or a query; any other address there is a 404. The same `Host` and `Origin` checks apply to it. A request's `Host` must be `127.0.0.1:<port>` or `localhost:<port>`; a request that changes anything (POST, PUT, DELETE) must carry an `Origin` of the same address, and a request with any other `Origin` is refused with 403. No CORS header is ever sent. A body is JSON with `Content-Type: application/json` and a `Content-Length`; the limit is about 34 MB (a 25 MB image in base64).

| Request | Answer |
|---|---|
| `GET /api/brands` | `{"brands": ["slug", ...]}`, alphabetical |
| `GET /api/brands/<slug>` | `{slug, status, client, summary, hub_problem, panels: [{title, text, problem, date}], moodboard: {exists, problem, items: [...]}}`; items newest first; text is plain, never escaped |
| `GET /api/brands/<slug>/images/<id>.<ext>` and `.../thumbs/<id>.<ext>` | the image bytes, with their own `Content-Type`; cacheable for a year (an id never changes), every other answer is `no-store` |
| `GET /api/brands/<slug>/links/<hash>-<version>.<ext>` | the thumbnail of an address's icon, the address being an item's `preview.url`; the version is the file's modification time (nanoseconds, hex) and only keys the browser's cache, so it is cacheable for a year like an image, and a file kept again is at a new address (ADR 008, amendment of 2026-10-18). `.../links/<hash>.<ext>` with no version still serves the file, with `Cache-Control: private, no-cache`; 404 when none is kept. An SVG icon (ADR 008, amendment of 2026-10-17) is the site's file as it came, answered with `Content-Type: image/svg+xml` and the policy `sandbox; default-src 'none'; style-src 'unsafe-inline'`, so a tab opened on it runs nothing |
| `POST /api/brands/<slug>/items` with `{description, source, image}` | 201 and the new item, at once; the fields are optional but at least one must be there; `image` is base64 or null; it looks nothing up (a `lookup` field in the body is ignored) |
| `POST /api/brands/<slug>/items` with `{card}` | 201 and the new item: a special card (ADR 009) in place of `description`, `source` and `image`, which must then be absent (400). `card` is `{kind: "text", title, body}`, `{kind: "colors", title, colors: [{hex, name}]}` (1 to 12; `title` and `name` may be empty) or `{kind: "type", name, notes}`; the server writes the block text and answers 422, with the reason, for anything that would not read back as the same card |
| `PUT /api/brands/<slug>/items/<key>` with `{card}` | 200 and the item as the brand view then shows it: the one place the app changes a block (ADR 009, decision 4). The block must be a special card, unchanged since shown (409 if not), and the new card of the same kind (422 otherwise); the note is rewritten through a temporary file and only that block's lines change. Nothing but `card` may be in the body (400) |
| `POST /api/brands/<slug>/items/<key>/lookup` | 200 and the item as the brand view shows it, after looking up its address (up to eight seconds); 422 for an item with no address or with an image of its own; 409 when no block has the key now (changed or removed); a text added twice has one key, and one lookup serves both |
| `DELETE /api/brands/<slug>/items/<key>` | `{"deleted": "<key>"}`; the key is the item's `key` from the brand view. If the block went but its image files could not be removed, still 200, with `"warning": "<plain text>"` added (never a path) |

An item is `{key, text, description, source, image, thumb, width, height, card, date, title, preview}`: `card` is null for an ordinary item, and for a block of one of the three special shapes of ADR 009 (and no image or address of its own) it is `{kind: "text", title, body}`, `{kind: "colors", title, colors: [{hex, name}]}` (hex in capitals) or `{kind: "type", name, notes, google}`, where `google` is the Google Fonts address the server wrote from the checked name, the only address a type card is linked to; `image` and `thumb` are addresses, or null for an item with no image (or whose embed was written by hand, which the app never serves); `width` and `height` are the thumbnail's size in pixels, or null when there is none or it cannot be read. `title` and `preview` come from the address lookup of ADR 008 and are null for an item with no address, an item with an image of its own, an address that was not looked up or whose lookup got nothing; `title` is the page's title as plain text, and `preview` is `{url, width, height}` of the page's icon (ADR 008, amendment of 2026-10-17: the name is kept, the page draws it small) as a thumbnail the app serves (so the page still loads nothing from another site). The server looks an address up only when asked, by the lookup call (ADR 008, amendment of 2026-10-17), so an add never waits. The lookup call fetches that page once (up to eight seconds); an address already looked up in that brand is not fetched again, and a failure is silent: the answer is still 200 with `title` and `preview` null. What is found is kept only if the item is still in the note once the answer is in. The title is never written into the note. Deleting an item also removes the kept lookup unless another block in the Moodboard has the same address. A panel's `date` is its note's frontmatter `created` (`YYYY-MM-DD`, or `YYYY-MM-DDTHH:MM` when it has a time; seconds and a zone are dropped), or null. An item's `date` is the one in its image id, as `YYYY-MM-DDTHH:MM`; in a brand's list an item with no image of the app's own takes the date of the item before it, in the order they were added, and one before any dated item has none. The page uses both to order its cards. `<slug>` is the folder name under `Brands/`, quoted in the address.

Statuses: 400 a body that cannot be read; 403 a refused origin or host, or a folder the app will not write in; 404 no such brand, image or route; 409 the brand has no Moodboard note (the app creates none), the item changed or is duplicated since it was shown, or the note changed while it was being written (nothing was written; try again); 408 the client stopped sending (30 seconds); 411 no length; 413 too big; 415 not JSON; 422 an image, address or description that cannot be taken; 500 something went wrong.
